# Upgrade Pi to 1.2.0 (mid-run compaction fix)

## Problem and root cause

A brand-new Pi session failed after ~11 minutes of work with:

```
ContextWindowExceededError: ... Context Window exceeded for given call.
Model=openai/gpt-6.1-sol, Max Input Tokens=922000, Got=1061104
```

In `@earendil-works/pi-coding-agent@0.80.10`, `AgentSession` only checked
compaction at `agent_end` and before the next user prompt. A single prompt
driving a long tool-calling loop never reached either checkpoint, so context
grew unbounded inside one run. Upstream fixed this in 0.84.4
([#6879](https://github.com/earendil-works/pi/issues/6879)) by compacting
between tool execution and the next assistant response, with a follow-up for
oversized trailing tool results in 0.86.0
([#9740](https://github.com/earendil-works/pi/issues/9740)).

Separately, the gateway's `Context Window exceeded` wording is not in pi-ai's
`OVERFLOW_PATTERNS` (still true in 1.2.0), so the post-run compact-and-retry
recovery never triggered.

## Changes

- `@earendil-works/pi-{ai,agent-core,coding-agent,tui}` 0.80.10 → 1.2.0 and
  `pi-mcp-adapter` 2.15.0 → 5.3.0 in runner-pi, runner-cli, daemon and
  bunny-agent-tui.
- `BunnyAgentResourceLoader`: forwards the new `getSystemPromptSource()` /
  `getAppendSystemPromptSources()` `ResourceLoader` methods.
- Patches rebased onto 1.2.0 and moved to `pnpm-workspace.yaml`
  (`package.json` `pnpm.patchedDependencies` removed):
  - `pi-ai`: embedded thought-signature stripping (unchanged) and new
    `/context ?window ?exceeded/i` overflow pattern.
  - `pi-coding-agent`: post-run continuation guard (`_continueAgentIfPossible`,
    upstream still calls `agent.continue()` unguarded after retry/compaction);
    `appendSystemPrompt` replaces the default "operating inside pi" preamble
    (now via the structured `preamble`/`addendum` sections); `piConfig`
    `.bunny` config dir.
  - Dropped: the 0.80.10 mid-run compaction patch (native in 1.2.0) and the
    `openai@6.26.0` uploads stub (pi-ai now depends on openai 7.19.0; the TUI
    runs end-to-end without it).
- Tests: mid-run compaction regression test against native behavior;
  behavioral continuation-guard test; new system-prompt patch test; MCP
  integration test updated for adapter 5.x reporting stale ctx as an
  `init_failed` result instead of throwing.

## Notes

In pi 1.2.0 `gpt-6.1-sol` is a built-in catalog model (`openai-responses`,
272k context window), so threshold compaction triggers near 256k
(`contextWindow - reserveTokens`), well below the gateway's 922k limit.
Live run: one prompt, 44 model calls, one mid-run compaction at 266k
tokens; the largest request was 253k.
