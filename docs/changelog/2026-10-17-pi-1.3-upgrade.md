# Upgrade Pi to 1.3.0 and fix SDK UTF-8 chunk decoding

## Why

Pi 1.3.0 (2026-10-15) fixes several failures Bunny runs hit through
OpenAI-compatible gateways:

- "The service is temporarily unavailable" and gateway "Unable to forward
  upstream stream" errors are now retried, including during compaction
  (earendil-works/pi#10965, #10920).
- Tool calls whose final arguments are malformed JSON fail validation and show
  the model what it sent, instead of silently running with only the fields
  parsed before the error (#10897); an invalid `\u` escape no longer drops
  fields (#10868).
- Anthropic / Bedrock requests no longer fail with 400 when an error tool
  result carries images (#10794).
- Repeated codemode timeouts no longer accumulate surviving workers (#10748).
- Internal Pi packages are pinned to exact versions (#10865).

Separately, the SDK decoded every network chunk with a fresh `TextDecoder`
without `stream: true`. A CJK character or emoji split across two chunks became
two U+FFFD replacement characters in the reply or tool output.

## Changes

- `@earendil-works/pi-{ai,agent-core,coding-agent,tui}` 1.2.0 → 1.3.0 and
  `pi-mcp-adapter` 5.3.0 → 5.3.1 in runner-pi, runner-cli, daemon and
  bunny-agent-tui.
- pi-ai patch rebased onto 1.3.0: upstream added the error-tool-image helpers at
  the top of `transform-messages.js`, so the first hunk no longer applied. The
  thought-signature strip and the `/context ?window ?exceeded/i` overflow
  pattern are unchanged.
- pi-coding-agent patch regenerated against 1.3.0 (line offsets only). It is
  still needed: upstream still calls `agent.continue()` unguarded after
  post-run retry/compaction.
- SDK: one streaming `TextDecoder` per SSE stream, flushed at end of body.
- SDK: daemon coding runs pass `timeout: 0` to `exec`. On exec-based sandboxes
  (`LocalMachine` / `LocalSandbox` / `SrtSandbox`), the daemon call is a curl
  command that inherited the 5-minute default command timeout, so every agent run
  longer than 5 minutes in local or self-hosted mode failed with
  `Command timed out after 300000ms`. Runs now end when they finish or when the
  abort signal fires. Sandock streams natively and ignores exec timeouts.
- runner-pi: load `pi-mcp-adapter` with jiti's transpile cache on, as Pi's own
  extension loader does. The adapter ships TypeScript sources, and a cold load
  spends 18–20s transpiling them synchronously, which blocks the daemon's event
  loop on the first MCP-enabled run of every process. With the cache, later
  processes load it in ~3s; jiti falls back to no cache when the directory is
  not writable. `mcp-integration.test.ts` exercises the cold load, which
  already took 19.4s on main CI against a 20s timeout. Its timeout is now 60s.

## Verification

- runner-pi 18 files / 210 tests, runner-cli 36, daemon 125, runner-harness 9,
  manager 132, sdk 53 — all pass; all packages build and typecheck.
- Patch tests are red with the pi-ai patch hunks removed and green with them.
- New `utf8-chunk-boundaries.test.ts` splits 你, 界 and 🐰 across chunks: red
  before the SDK fix (`���好，世��…`), green after.
- runner-cli and the built daemon (`POST /api/coding/run`) against a local
  OpenAI-compatible fake: first request returns 503 "The service is temporarily
  unavailable", Pi retries, runs a `bash` tool call and finishes with
  `finishReason: stop`.
- A session written by the published 0.9.62 daemon (Pi 1.2.0) resumes on the
  1.3.0 daemon with its full history.

- MCP adapter load: 20.3s / 18.0s cold without the cache; 20.6s then 2.9s with
  it. The integration test took 21.0s cold and 2.4s warm.

- New `daemon-run-timeout.test.ts`, with a real `LocalMachine` (300ms default
  timeout) against a daemon that streams for ~1s: red before (`Command timed out
  after 300ms`, only "a" received), green after ("abcde").
- Real provider: the 1.3.0 daemon with `openai:gpt-6.1-sol` through an
  OpenAI-compatible gateway ran a `bash` tool call and finished with
  `finishReason: stop` in 5s.
- End to end inside Buda (vikadata/kapps#8018), with the local runtime pointed at
  this daemon and the SDK build swapped into Buda:
  - A ~115k-character Chinese reply was saved with 12 and 4 U+FFFD characters
    using the 0.9.62 SDK, and 0 and 0 with this SDK.
  - An 11-minute `bash` run completed in local mode. With the 0.9.62 SDK it
    died at exactly 5 minutes.

Not verified: the published Docker image build. The
first MCP-enabled run of a fresh sandbox still pays the cold compile; warming
the cache at image build time would remove it.
